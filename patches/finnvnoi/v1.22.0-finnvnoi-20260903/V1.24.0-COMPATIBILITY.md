# v1.24.0 compatibility report

Tested against upstream tag `v1.24.0` (`84fde5a1ed5e0d5a58ccb3ec4b82938b059bf8c5`).

## Verdict

The exact v1.22.0 production overlay **does not apply directly** to v1.24.0. A history-aware merge also leaves 58 unresolved paths, mainly because v1.24.0 substantially changed proxy routing, HTTP bridge recovery, request logging, model sources, settings, and dashboard code.

No complete FinnVnoi commit is patch-equivalent to an upstream v1.24.0 commit. Some concepts overlap, so those portions should be skipped or manually composed rather than forcing the old implementation over newer upstream code.

## Trial evidence

- Exact full overlay: failed `git apply --check` across many evolved files.
- History-aware merge: 58 unresolved paths.
- Individual historical commits tested independently on clean v1.24.0:
  - clean textual apply: expiring key prefix, CPA import, usage bulk endpoint, preserve-window usage, CPA/expiry adaptation;
  - conflicts requiring manual composition: warmup recovery, Anthropic Messages, stream drain, hourly/lifetime limits, GPT-5.6 diagnostics, quota shop, exact amounts;
  - consolidated routing/dashboard checkpoint: 43 conflict paths.

A clean textual cherry-pick is not proof of semantic compatibility; each retained patch still needs v1.24-specific tests.

## Recommended port order

1. API-key compatibility: expiry prefix, CPA import, usage bulk.
2. API-key limit schema/semantics, including dormant first-use countdown.
3. Quota shop and expiry auto-extension migrations.
4. Usage activity aggregates.
5. Model-source fields, estimation, auto-pause.
6. Routing/fallback behavior while retaining v1.24 bridge and recovery internals.
7. Anthropic Messages and Codex-specific SSE error behavior.
8. Dashboard/i18n.

## Required gates before production

- Alembic upgrade on a copy of the production database.
- Targeted API-key, quota shop, usage, model-source, fallback, Anthropic, exception-handler, and HTTP-bridge tests.
- Full backend test/lint suite.
- Frontend typecheck, tests, and production build.
- Staging smoke for all routing modes and API compatibility endpoints.

The v1.24.0 trial was isolated; no production source, database, configuration, or service was changed.
