# FinnVnoi patches vs Codex-LB v1.24.0

Tested on 2026-09-03 against upstream tag `v1.24.0` (`84fde5a1`).

## Verdict

The complete v1.22.0 FinnVnoi overlay **does not apply cleanly** to v1.24.0 and must not be forced.
A history-aware merge leaves 58 unresolved paths. The largest conflicts are in proxy routing,
HTTP bridge recovery, API-key reservations, model sources, settings, migrations, and the frontend.
Several v1.24.0 changes touch the same code and supersede portions of older local recovery logic.

## Application experiment

- Exact v1.22.0 overlay on v1.24.0: rejected in many core paths.
- History-aware merge of the source snapshot: 58 unresolved files.
- Isolated older commits that apply textually cleanly include expiring-key prefix, CPA import,
  usage bulk, usage-preserving window edits, and CPA/expiring-key compatibility. A clean textual
  cherry-pick is not proof of semantic compatibility; each still requires focused tests.
- The large resilient-routing checkpoint conflicts in 43 files by itself and requires a redesign-level port.

## Recommended port order

1. Rebase/merge the migration graph and test a copied production database.
2. Port low-coupling API-key/account compatibility features.
3. Port API-key windows, dormant countdown, quota shop, and usage endpoints.
4. Compose model-source schema/service changes with v1.24 embeddings and reasoning metadata.
5. Port Anthropic and mixed routing behavior last, preserving all v1.24 bridge/recovery code.
6. Port frontend contracts, locale, mocks, and tests.
7. Run focused suites, full backend tests, frontend typecheck/tests/build, then staging smoke.

No v1.24.0 trial changes were applied to production.
